# Data Processing Engine

Потокова аналітика продажів інтернет-магазину. Для запуску потрібен Python 3.10 або новіший. Проєкт використовує стандартну бібліотеку.

## Запуск

Розпакуйте архів, відкрийте папку `data_processing_engine` у PyCharm і запустіть `main.py`. З термінала в папці проєкту:

```bash
python3 main.py
python3 main.py --memory
python3 main.py data/sales.csv --category Accessories --batch-size 32
```

Шлях до CSV можна передати першим аргументом. Без нього програма використовує `data/sales.csv` зі 120 демонстраційними записами. Параметр `--memory` додатково запускає порівняння споживання пам'яті.

## Формат CSV

| Поле | Тип | Значення |
| --- | --- | --- |
| `id` | `int` | Додатний ідентифікатор продажу |
| `product` | `str` | Назва товару |
| `category` | `str` | Категорія товару |
| `quantity` | `int` | Додатна кількість одиниць |
| `price` | `float` | Ціна за одиницю, невід'ємне скінченне число |
| `status` | `str` | Статус продажу, наприклад `completed` або `cancelled` |

Файл має бути в UTF-8 і містити заголовок із шістьма зазначеними полями. Програма повідомляє номер некоректного рядка й завершується з помилкою. Для фільтра статусу регістр не має значення.

## Ітератори та генератори

- `SalesIterator` приймає список або будь-яке інше ітероване джерело. За потреби пропускає продажі, категорія яких не збігається із заданою.
- `read_sales()` послідовно читає й перевіряє записи. `filter_sales()` пропускає їх за заданим статусом.
- `calculate_revenue()` повертає накопичену виручку після кожного отриманого продажу.
- `generate_batches()` повертає пакети заданого розміру, включно з останнім неповним пакетом.
- `generate_top_products()` приймає підсумки виручки за товарами й повертає лідерів за виручкою.

Усі етапи конвеєра виконують окремі генератори.

| Етап | Генератор |
| --- | --- |
| Читання CSV | `read_csv_rows()` |
| Валідація | `validate_sales()` |
| Підрахунок усіх записів | `count_sales()` |
| Фільтр статусу | `filter_sales()` |
| Розрахунок виручки за записом | `transform_sales()` |
| Формування пакетів | `generate_batches()` |
| Формування підсумкового звіту | `analyze_batches()` |

Звіт рахує всі записи, а виручку, середній чек і рейтинги визначає за продажами зі статусом `completed`. Виручка за записом дорівнює ціні одиниці, помноженій на кількість, з округленням до сотих. Середній чек дорівнює виручці, поділеній на кількість завершених записів. Популярність товару вимірюється кількістю проданих одиниць. При однакових показниках перемагає перша назва за алфавітним порядком Python.

Звіт для демонстраційного CSV містить 120 продажів, 95 завершених, загальну виручку 19 066,21 та середній чек 200,70. Найпопулярніший товар — Mouse, категорія з найбільшою виручкою — Electronics.

## Додаткові генератори

Із `sales_ids()` можна взяти потрібну кількість послідовних ID через `itertools.islice()`. `fibonacci(n)` повертає перші `n` чисел Фібоначчі, починаючи з нуля. `flatten_nested()` рекурсивно обходить вкладені списки, кортежі та значення словників.

## Експеримент із пам'яттю

`tracemalloc` окремо вимірює пік виділень пам'яті Python для двох способів розрахунку виручки. Перший завантажує весь CSV у список об'єктів `Sale`. Другий передає записи генератором. Обидва фільтрують завершені продажі, використовують однакову формулу і перевіряють збіг результатів.

| Файл | Записів | Пік зі списком | Пік із генератором |
| --- | ---: | ---: | ---: |
| Демонстраційний `sales.csv` | 120 | 193 901 байт | 161 279 байт |
| Розширений CSV із тим самим набором товарів | 120 000 | 39 982 833 байти | 177 520 байтів |

Другий файл отримано 1000-кратним повторенням демонстраційних записів із послідовними унікальними ID. Для нього обидва способи дали виручку 19 066 210,00. Вимірювання виконано на Python 3.14.8, і точні значення залежать від середовища.

У цьому експерименті список на 120 000 записів використав приблизно у 225 разів більше пам'яті, ніж генератор. Для повного аналітичного звіту пам'ять також залежить від розміру пакета та кількості різних товарів і категорій, для яких збираються підсумки.
